# 城市交通路径导航系统

《数据结构实践》课程实践任务书一 —— 基于图论算法的图形界面路径导航模拟系统。

## 一、功能简介

| 模块 | 说明 |
| --- | --- |
| 地图加载与存储 | 支持从 `.txt` / `.json` 文件加载站点（坐标、站名）与线路（连接关系、距离权重） |
| 最快路径 | Dijkstra 算法（基于距离 / 时间权重） |
| 最少换乘 | BFS 算法（基于层级搜索，求经过站数最少的路径） |
| 启发式搜索 | A* 算法，`f(n) = g(n) + h(n)`，启发函数 `h(n)` 为欧几里得距离 |
| 交互式界面 | 可视化站点网络；下拉框或点击地图选择起终点；高亮路径并列出站点清单；动画演示搜索过程 |
| 扩展功能 | 动态增删站点 / 区间；保存数据；搜索效率对比（耗时、扩展节点数） |

## 二、运行环境

- Python 3.8 及以上（开发测试环境为 3.14）
- **零第三方依赖**，仅使用标准库：`tkinter`、`heapq`、`json`、`math`、`collections`、`time`、`dataclasses`
- 若 Python 未随附 Tkinter，请补装对应发行版的 tk 支持包

## 三、启动方法

在项目目录下执行：

```bash
# 使用默认数据（郑州地铁，中等规模 data/zhengzhou_metro.json）
python main.py

# 或指定数据文件（.txt / .json 均可）
python main.py data/metro.json              # 示例小网络（13 站）
python main.py data/zhengzhou_metro.json    # 郑州地铁（233 站）
python main.py data/beijing_metro.json      # 北京地铁（411 站）
```

## 四、操作说明

1. **选择起终点**：可直接点击地图上的站点（第一次点击设起点，第二次设终点），也可用顶部下拉框选择。
2. **选择算法**：顶部单选按钮切换 Dijkstra / BFS / A*。
3. **搜索**：点击“搜索路径”，画布以红色高亮路径，右侧列出经过站点、路径权重、程序耗时与扩展节点数。
4. **缩放 / 平移**：鼠标**滚轮缩放**（以光标为锚点），**按住左键拖拽平移**，点击“重置视图”回到全图。
5. **查看站名**：悬停站点可在状态栏查看站名与途经线路；勾选“显示站名”可在图上直接标注（大网络默认关闭以避免重叠）。
6. **动画演示**：勾选“动画演示”后，会先逐步点亮搜索扩展过的节点，再逐段画出最终路径。
7. **数据管理**：“加载数据…”读取外部文件；“保存数据…”导出为 JSON；“添加站点 / 删除站点 / 添加区间”实现动态增删。
8. **异常处理**：当起终点不连通时，程序会给出明确提示而不是崩溃。

## 五、数据格式

### JSON（推荐）

```json
{
  "name": "示例城市地铁网络",
  "stations": [
    { "id": "S01", "name": "西苑站", "x": 5, "y": 20 }
  ],
  "edges": [
    { "from": "S01", "to": "S02", "weight": 7.0, "line": "1号线" }
  ]
}
```

### TXT（`#` 开头为注释）

```
# 站点: station, 编号, 名称, 横坐标, 纵坐标
station, S01, 西苑站, 5, 20
# 区间: edge, 起点, 终点, 距离, 线路名
edge, S01, S02, 7.0, 1号线
```

> 说明：站点坐标 `(x, y)` 单位为千米，既用于画布定位，也是 A* 欧几里得启发函数 `h(n)` 的依据；区间 `weight` 为两站间距离，保证 `h(n) ≤ 真实距离`，从而 A* 结果与 Dijkstra 一致（最优且可采纳）。

## 六、代码结构

| 文件 | 职责 |
| --- | --- |
| `graph.py` | 图数据结构（`Station`、`Edge`、`Graph`，邻接表存储） |
| `solver.py` | 算法引擎（`Solver`、`dijkstra`、`bfs`、`astar`、`SearchResult`） |
| `data_loader.py` | 数据加载 / 保存（JSON 与 TXT 两种格式，支持线路配色） |
| `ui.py` | 图形界面（`MetroApp`，基于 Tkinter，支持缩放 / 平移 / 悬停） |
| `main.py` | 程序入口 |
| `scripts/import_metro.py` | 地铁数据导入脚本（通用，高德数据 → 本项目格式） |

三者（Graph / Solver / UI）相互解耦，符合任务书的面向对象设计要求。

## 七、数据文件

| 文件 | 说明 |
| --- | --- |
| `data/zhengzhou_metro.json` | **郑州地铁（默认加载）**：13 条线路、233 个站点、270 段区间（中等规模，站名默认显示） |
| `data/beijing_metro.json` | **北京地铁完整数据**：27 条线路、411 个站点、497 段区间、105 个换乘站 |
| `data/metro.json` / `metro.txt` | 示例小网络：4 条线路、13 个站点（便于入门测试） |

> 数据由 `scripts/import_metro.py` 从高德地图地铁接口自动转换而来，支持任意城市：
> `http://map.amap.com/service/subway?_1469083453978&srhdata=<adcode>_drw_<城市拼音>.json`
> 经纬度经等距圆柱投影转换为以城市质心为原点的千米坐标，边权重取相邻站点距离，
> 保证 A* 的欧几里得启发函数可采纳。原始数据见 `scripts/amap_*.json`，
> 重新生成命令：
> `python scripts/import_metro.py scripts/amap_zhengzhou.json data/zhengzhou_metro.json`

一个典型对比结果（示例网络，机场 → 南站）：

| 算法 | 路径 | 路径权重 |
| --- | --- | --- |
| Dijkstra / A* | 机场 → 科技园 → 市中心 → 南湖 → 南站 | 41.20 km（最短距离） |
| BFS | 机场 → 科技园 → 火车站 → 南站 | 3 站段（最少换乘） |

可见 Dijkstra 追求距离最短，BFS 追求换乘最少，二者目标不同、结果不同。

## 八、网页版（可直接双击打开，无需 Python）

在 `web/` 目录下提供了一套功能完全等价、可直接在浏览器打开的网页版界面（画风更精致、字体更美观）：

| 文件 | 说明 |
| --- | --- |
| `web/index.html` | **最终成品**：自包含单文件，内置郑州 / 北京 / 示例三套数据，双击即可在浏览器打开 |
| `web/template.html` | 网页源码（HTML + CSS + JS），数据由占位符注入 |
| `web/build.py` | 构建脚本：把 `data/*.json` 内嵌进模板，生成 `web/index.html` |
| `web/test.js` | 算法自检（Node 环境）：校验 Dijkstra ≡ A*、BFS 最少换乘 |

- 数据之所以**内嵌**进 HTML，是因为浏览器以 `file://` 协议打开本地文件时，`fetch()` 读取同目录 JSON 会被同源策略拦截；内嵌后无需任何服务器即可运行。
- 网页版功能与桌面版一致：三种算法、点击地图或输入站名选择起终点、路径高亮与站点清单、动画演示、缩放平移、悬停提示、加载 / 保存数据、动态增删站点与区间。
- 重新构建：`python web/build.py`；算法自检：`node web/test.js`。
